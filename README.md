# domain-slm

**A small domain language model you can trust.** A tokenizer and a classifier
trained from scratch on CPU in seconds — and an evaluation that **refuses to
report a number** when the split it was measured on overlaps the data the model
was trained on.

A reported accuracy is a claim about data the model has not seen. When part of
the evaluation set is also in the training set, the number is partly a
memorisation score — and **nothing in the number says how much**. A contaminated
96% and a clean 96% look identical.

```bash
dslm evaluate --splits splits/ --model model/ --null holdout.jsonl.gz
echo $?   # 0 held, 2 a gate failed, 3 the tool could not run
```

When the gate fails there is no accuracy in the JSON, no passing case in the
JUnit XML, and the Markdown summary says why instead of printing a figure with a
warning above it. A warning above a number is read as a number.

## The finding this repository was built to publish

The usual contamination check is *"13-gram containment at or above 0.5"*, taken
from the technical reports of several published models. This project inherited
it, measured it, and found that **on short formulaic text the number it produces
is background, not signal.**

The `holdout` corpus here is generated by the same grammar with a different
seed, so it shares no record with training *by construction*. Scored against
training by the published rule:

| Corpus | Hit rate |
| --- | --- |
| `holdout` — **cannot** be contaminated | 1.80% |
| the genuine test split | 1.25% |

Data that cannot be contaminated scores *higher* than data that might be. The
rule cannot even order the two correctly, so a threshold on its output decides
on noise. Maintenance write-ups are formulaic; two entirely unrelated work
orders routinely share a thirteen-word run.

**So the null calibrates the threshold, not the verdict.** Score a provably
disjoint corpus, take a high quantile of that distribution as the threshold
(0.846 here, not 0.5), and the reported rate starts meaning what it says:

| Contamination injected | Measured |
| --- | --- |
| 0% | 0.00% |
| 5% | 4.89% |
| 10% | 9.96% |
| 25% | 25.00% |

Within 0.11 points. That is no longer a flag — it is an estimate of how much of
the evaluation set the model has already seen. `scripts/check-pipeline.py`
asserts it on every push.

**And with no null corpus, the tool refuses to gate at all.** A number nobody
can interpret is not a gate.

## The second finding: the control won

Two models are trained, always, and compared with a significance test:

| Model | Accuracy | Parameters |
| --- | --- | --- |
| majority class | 11.1% | 0 |
| **multinomial naive Bayes** | **92.03%** | **12,300** |
| neural (embeddings → mean pool → MLP) | 92.39% | 55,020 |
| ceiling imposed by label noise | 96.1% | — |

McNemar's exact test over the 14 records they disagree about: **p = 0.79.** The
two are statistically indistinguishable, and the linear control gets there with
a fifth of the parameters.

That is the honest result, so it is the one on the front page. A comparison
nobody ran is not evidence that the complicated thing won — and this repository
would rather publish a control that beat it than quietly not measure.

## The pipeline

```bash
dslm synth     --plan main     --out corpus.jsonl.gz     # generate, with provenance
dslm curate    --corpus corpus.jsonl.gz --out clean.jsonl.gz --card DATA-CARD.md
dslm split     --corpus clean.jsonl.gz  --out-dir splits/
dslm train     --splits splits/ --out-dir model/
dslm evaluate  --splits splits/ --model model/ --null holdout.jsonl.gz
```

Each step is a gate as well as a stage.

**`curate`** finds near-duplicates with MinHash and LSH — the same write-up with
one station code changed, which a hash set sees as two records and a model sees
as one. It reports what it *would* remove; removing is a separate, opt-in act.

**`split`** keeps every duplicate cluster on one side. Deduplicating first is
not sufficient on its own: the duplicate is gone, but a *related* record may
remain.

**`train`** fits the tokenizer, the neural model and the linear control. Both
models, always.

**`evaluate`** runs the contamination gate **before** computing a metric, then
compares against a committed baseline and fails on a regression.

## Two things that are measured here rather than assumed

**The conventional deduplication parameters do not transfer to short records.**
A record of `n` words has `S = n − w + 1` shingles, so a one-word edit caps the
similarity at `(S − w)/(S + w)`. On a 21-word record that is 0.63 at the
conventional 5-word shingle — *below* the conventional 0.8 threshold, so the
check reports that a corpus full of near-duplicates contains none. This project
uses a 3-word shingle at 0.6, chosen by measurement, and the formula is asserted
in the test suite. See [docs/curation.md](docs/curation.md).

**A trained model is not bit-identical across platforms, and this project
measured how far.** Uniform initialisation is used rather than normal because
`standard_normal`'s ziggurat tail calls `log`, and libm's `log` differs by one
unit in the last place between Windows and Linux — one value in 32,768, which
then propagates through every weight. That fixes initialisation but not
training: after 30 steps the loss is bit-identical while 1,344 of 55,872 weights
differ, by at most 2.4e-14 relative. So the corpus, split and tokenizer are
gated by **digest**, and the model by **metrics within a stated tolerance**.
See [docs/reproducibility.md](docs/reproducibility.md).

## The corpus is generated, and says so

Aircraft maintenance work orders, labelled with their ATA 100 chapter. Every
record carries its `source` and `license` as **required fields**, and the header
of every corpus says it was synthesised.

Real maintenance records are somebody's commercial data; publishing them is a
licensing question with a wrong answer. Generating them is also strictly better
for what this repository has to demonstrate: **the duplicates and the
contamination are planted at known rates**, so the deduplicator and the gate can
be asserted to find a known answer rather than merely to produce one.

The task is deliberately hard. An earlier version of the grammar gave every
chapter a disjoint vocabulary and both models scored 100.00% — a number that
measured the grammar, not the model. It now shares vocabulary across chapters
and mislabels 4% of records on purpose, which is what real maintenance data
does and what puts a real ceiling under any accuracy claim.

## Install

```bash
uv sync --locked --group dev
uv run dslm doctor
```

Five runtime dependencies. NumPy is the only non-pure-Python one, and the model
is written out in it rather than delegated to a framework — because *can two
machines train the same model?* is the question this repository is about, and
taking on a framework would answer it by delegation.

Or the container, which runs as a non-root user:

```bash
docker run --rm --network none domain-slm:local doctor
```

## Guarantees, stated precisely

- **A record has no field for free text beyond the work order itself.**
  `extra="forbid"` refuses one at validation.
- **Nothing reaches a network.** There is no HTTP client, no socket and no
  credential setting anywhere in the package; the test suite asserts it over the
  source.
- **A check that could not be applied is never reported as passed.** Too-short
  records, missing baselines and uncalibrated thresholds each get their own
  refusal.

# Examples

Everything here is generated, runnable, and checked by CI. Nothing was scraped
or copied from an operator's maintenance system.

## What is here

| Path | What it is |
| --- | --- |
| `corpus.jsonl.gz` | 6,000 synthesised work orders, 12 ATA chapters |
| `holdout.jsonl.gz` | 1,500 more from a different seed — the **null corpus** |
| `clean.jsonl.gz` | The corpus after near-duplicate removal |
| `splits/` | train / dev / test, grouped so no cluster straddles them |
| `model/` | The trained tokenizer, weights and metadata |
| `baseline.json` | What the models scored, for the regression gate |
| `DATA-CARD.md` | Generated from the records, never written by hand |
| `quickstart.py` | The whole pipeline in one file |
| `contamination_demo.py` | Why the published threshold fails, in three measurements |
| `tokenizer_demo.py` | What a domain vocabulary buys, measured |

The Python files are documentation that executes. CI runs all three on every
push, because an example that stops working is a README that lies.

## Rebuild all of it

```bash
python tasks.py corpus     # synth, curate, split, data card
python tasks.py train      # tokenizer + both models
python tasks.py baseline   # re-record what they scored
```

Deterministic: the same plan gives the same records on every machine, and
`python tasks.py corpus-check` verifies the committed corpora still match by
digest rather than by regenerating and diffing.

The corpora are gzipped with a zero timestamp in the gzip member, so the same
corpus written twice produces the same bytes and a diff means a real change.

## The null corpus, and why it exists

`holdout.jsonl.gz` is generated by the same grammar with a different seed, so it
shares no record with training **by construction**. That makes it the instrument
the contamination gate is calibrated against — the containment level that
provably clean data reaches, which turns out to be nothing like the published
threshold.

It collides with training on exactly **one record in 1,500**. Two corpora from
one grammar really can produce the same sentence, and `--drop-shared` removes
those and reports the count rather than hiding it.

## The corpus is synthesised, and says so

Every record carries its provenance as a required field, and the header says
what it is:

```json
{
  "generated": "true",
  "note": "Synthesised maintenance records. Nothing here was captured from a real operator, and no result over it is a claim about real maintenance data.",
  "plan": "main",
  "seed": "20260908",
  "planted_exact_duplicates": "180",
  "planted_near_duplicates": "240",
  "label_noise": "0.04"
}
```

Real maintenance records are somebody's commercial data; publishing them is a
licensing question with a wrong answer. Generating them is also strictly better
for what this repository demonstrates: **the duplicates and the contamination
are planted at known rates**, so the deduplicator and the gate can be asserted
to find a known answer rather than merely to produce one.

## The task is deliberately hard

The first version of this grammar gave every chapter a disjoint vocabulary.
Both models scored **100.00%** — a number that measured the grammar, not the
model, and made the comparison between them vacuous.

Two changes fixed it, and both are things real maintenance data does:

**Chapters share vocabulary.** 45% of slots are drawn from a chapter-neutral
pool — `control valve`, `position sensor`, `intermittent fault reported`. A
write-up made entirely of those is genuinely ambiguous.

**4% of records are mislabelled**, with the text describing the true chapter and
only the recorded label wrong — which is how a mis-chaptered work order actually
looks. That puts a real ceiling of **96.1%** under any accuracy claim, and the
generator records which records it corrupted so the ceiling is computed rather
than asserted.

## What the shipped artefacts score

| Model | Accuracy | Parameters |
| --- | --- | --- |
| majority class | 11.1% | 0 |
| naive Bayes | 92.03% | 12,300 |
| neural | 92.39% | 55,020 |
| ceiling | 96.1% | — |

McNemar's exact test over the 14 discordant records: **p = 0.79**. The two are
statistically indistinguishable.

Contamination on the shipped split: **0.00%** at a calibrated threshold of
0.846, against the published threshold of 0.5 that would call 1.6% of provably
disjoint data contaminated.

## Running the demos

```bash
python examples/quickstart.py
python examples/contamination_demo.py
python examples/tokenizer_demo.py
```

Or all three: `python tasks.py examples`.

`contamination_demo.py` is the one to read first — it is the argument this
repository is built on, in three measurements and about forty lines.

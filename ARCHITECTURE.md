# Architecture

How this is put together, and the decisions a reader is most likely to argue
with — recorded with the reasoning and, where there is one, with the
measurement that settled it.

## The shape of it

One command line over five libraries. Nothing runs as a service; there is no
database and no state between invocations. Every stage is a pure function of its
inputs and a seed.

```
  synth ─▶ curate ─▶ split ─▶ train ─▶ evaluate ─▶ exit 0 | 2
             │         │        │          │
          data card  digest   model     contamination gate, then
                                        the regression gate, then
                                        JSON · JUnit · Markdown
```

| Package | What lives there |
| --- | --- |
| `dslm.corpus` | Records, corpora, the generator, curation, splitting, **contamination** |
| `dslm.tokenizer` | Byte-pair encoding, trained from scratch |
| `dslm.model` | Features, the neural classifier, the linear control, persistence |
| `dslm.evaluate` | Metrics, significance, the committed baseline, three renderers |
| `dslm.cli` | Argument parsing, exit codes, and nothing else |

Imports run downward. `evaluate` knows about arrays and not about files;
`corpus` knows about neither. `cli` is the only module that touches `argparse`,
`sys.exit` or where files live, which is what makes every command testable
in-process as well as end to end.

## ADR-001 — The contamination threshold is calibrated against a null, not fixed

**Status:** accepted. The decision this repository exists for.

**Context.** The published rule is "13-gram containment ≥ 0.5". It was
inherited, then measured.

**The measurement.** The `holdout` corpus is generated by the same grammar with
a different seed, so it shares no record with training by construction. Scored
against training by the published rule it comes out at **1.80%**, while the
genuine test split comes out at **1.25%**. Data that *cannot* be contaminated
scores higher than data that might be. Restricting the index to n-grams
appearing in exactly one training record halves both numbers and leaves the
ordering just as wrong (0.54% against 1.13%).

Nothing is wrong with the arithmetic. Maintenance write-ups are formulaic, so
two unrelated work orders share thirteen-word runs. On web-scale prose, where
the rule was calibrated, that background is near zero and the rule works.

**Decision.** Score a corpus known to be disjoint, and set the threshold at a
high quantile of *that* distribution — 0.846 here rather than 0.5. Without a
null corpus the tool reports the raw rate and **refuses to gate on it**.

**Consequences.** The reported rate becomes an estimate rather than a flag.
Injecting contamination at a known rate and measuring it back:

| Injected | Measured |
| --- | --- |
| 0% | 0.00% |
| 5% | 4.89% |
| 10% | 9.96% |
| 25% | 25.00% |

An earlier version of this decision calibrated the *rate* rather than the
threshold — comparing the evaluation set's hit rate against the null's and
failing on the excess. It was measured too, and it was too blunt: a clean split
sits below the background, so a **10% verbatim injection passed**. The failure
is recorded here because the fix is not obvious from the outside.

## ADR-002 — Two models, always, with a significance test

**Status:** accepted.

**Context.** Every claim that a neural model is worth having is a comparison,
and most published ones omit the other side of it.

**Decision.** `dslm train` fits a multinomial naive Bayes control alongside the
neural classifier, and `dslm evaluate` scores both and compares them with
McNemar's exact test. Neither is optional.

**Consequences.** On this corpus the control scores 92.03% against the neural
model's 92.39%, with a fifth of the parameters, and McNemar's test over the 14
discordant records gives **p = 0.79** — statistically indistinguishable.

That is the result, so it is on the front page. It also disciplines the
architecture: mean pooling rather than attention is the right choice for a
twenty-word record when a bag of counts is already this close, and adding
attention would be answering a question nobody asked.

The exact binomial form is used rather than chi-squared because the
approximation needs roughly 25 discordant pairs and two similar models on a few
hundred records routinely produce fewer.

## ADR-003 — Digest gates for integers, tolerance gates for floats

**Status:** accepted.

**Context.** The project wanted one rule: every artefact checked by content
address. That was measured and found to be impossible for one of them.

**The measurement.** With NumPy pinned, on Windows and Linux, after 30 training
steps: the loss is **bit-identical**, and **1,344 of 55,872 weights differ**, by
at most 2.4e-14 relative. Accumulation order inside a matrix multiply is a
property of the BLAS build and no seed controls it.

A separate finding on the way: `standard_normal` uses a ziggurat whose rare tail
branch calls `log`, and libm's `log` differs by one unit in the last place
between the two platforms — exactly one value in 32,768 differed, and that
single bit then propagated through every subsequent weight. Initialisation is
therefore **uniform**, which is integer-to-float only and bit-identical
everywhere.

**Decision.** Two classes of artefact, gated differently:

| Artefact | Made of | Gate |
| --- | --- | --- |
| corpus, split, tokenizer | integers and strings | **digest** |
| model weights | float64 | **metrics within a stated tolerance** |

**Consequences.** `dslm check` compares corpus digests exactly. The regression
gate allows a half-point drop. Claiming a byte-exact model across platforms
would be a claim this project measured and found to be false.

## ADR-004 — The corpus is synthesised, deterministically, and says so

**Status:** accepted, and consistent with the telemetry tool elsewhere in this
series.

**Context.** A corpus is the one part of a machine-learning repository that
cannot be hand-waved. Real maintenance records are somebody's commercial data.

**Decision.** Every record is generated from a seeded grammar, carries `source`
and `license` as **required fields**, and every corpus header states that it was
synthesised. `random.Random` rather than NumPy's generator: everything here is a
choice among strings, so the stdlib Mersenne Twister is exactly reproducible
with none of the libm divergence ADR-003 records.

**Consequences.** The duplicates and the contamination are planted **at known
rates**, so the deduplicator and the gate can be asserted to find a known answer
rather than merely to produce one. That is what `tests/meta/` is built on.

The first version of the grammar gave every chapter a disjoint vocabulary and
both models scored 100.00% — a number that measured the grammar rather than the
model, and made the comparison in ADR-002 vacuous. The grammar now shares
vocabulary across chapters and mislabels 4% of records deliberately, which is
what real maintenance data does and what puts a genuine ceiling under any
accuracy claim.

## ADR-005 — Deduplication parameters are derived from the record length

**Status:** accepted.

**Context.** The conventional near-duplicate setting is a 5-word shingle at a
0.8 Jaccard threshold, from web-scale document deduplication.

**The arithmetic.** A record of `n` words yields `S = n − w + 1` shingles.
Changing one word destroys at most `w` on each side, so the best achievable
similarity between a record and its one-word variant is `(S − w)/(S + w)`. On a
21-word record: 0.78 at `w=3`, 0.70 at `w=4`, **0.63 at `w=5`**.

So the conventional setting cannot detect a one-word edit *at all* on records
this short — it reports that a corpus full of near-duplicates contains none. The
formula predicts the measured median to three decimal places at every width, and
the test suite asserts it.

**Decision.** A 3-word shingle at a 0.6 threshold, chosen by measurement: a
planted one-word variant scores 0.727 or above, an unrelated pair 0.471 or
below, and 0.6 sits in the gap with margin on both sides.

**Consequences.** And the banding has to match. 16 bands of 8 rows — the
textbook default, and this project's first setting — puts the S-curve midpoint
at 0.707, so a pair sitting *at* the 0.6 threshold is found barely one time in
four. Recall over the planted duplicates was 0.950. At 32 bands of 4 rows the
midpoint is 0.420 and recall is **1.000**, for more candidate pairs to verify
exactly — which is the right side of the trade, because banding exists to avoid
18 million comparisons rather than to be as cheap as possible.

A unit test caught this.

## ADR-006 — Splitting groups by cluster, and the gate checks anyway

**Status:** accepted.

**Context.** A record and its near-duplicate on opposite sides of a split
produce a reported accuracy that is partly a memorisation score.

**Decision.** `split_corpus` takes the duplicate clusters and keeps every member
on one side, merging transitively with an optional metadata grouping key.
Deduplicating first is *not* treated as sufficient: the duplicate is gone, but a
related record may remain.

**Consequences.** Grouping still is not sufficient either, and the honest
position is that no amount of care upstream replaces measuring the result. That
is why the contamination gate exists downstream of this module and measures the
splits it produced rather than trusting that it did its job.

## ADR-007 — NumPy, and no framework

**Status:** accepted.

**Context.** The model needs an array library. The obvious choice is a deep
learning framework.

**Decision.** NumPy, with the forward and backward passes written out.

**Consequences.** The reproducibility question in ADR-003 is the one this
repository is actually about, and a framework would answer it by delegation.
A framework is also a 900 MB dependency for a model with three weight matrices,
and it puts a stack between what the maths says and what the code does.

The cost is real: no GPU, no attention, no autograd, and a model that would not
scale. All of which is correct for a model whose point is that it trains on a
laptop in five seconds and is beaten by naive Bayes.

NumPy is the first non-pure-Python runtime dependency in this series, and the
justification is the same one that kept the telemetry tool on stdlib `urllib`:
take the smallest thing that does the job.

## ADR-008 — Exit codes are the interface, including argparse's

**Status:** accepted.

**Decision.**

| Code | Meaning |
| --- | --- |
| 0 | Every gate that could be applied held |
| 1 | The command line was used wrongly |
| 2 | A gate failed |
| 3 | The tool could not produce a verdict |

**Consequences.** `argparse` exits **2** on a usage error by default, which this
tool documents as *a gate failed* — so a mistyped flag and a contaminated corpus
would be indistinguishable to a CI job. The parser is subclassed to exit 1
instead, and the subparsers inherit it. An end-to-end test caught this; nothing
in-process could have.

## ADR-009 — Curation reports; removal is a separate act

**Status:** accepted.

**Context.** A curation step that silently removed a quarter of a corpus would
be the most consequential unlogged action in the pipeline.

**Decision.** `find_duplicates` returns clusters and changes nothing.
`apply_curation` removes them. The CLI writes a deduplicated corpus only when
`--out` is given, and the data card is generated from the records rather than
written by hand.

**Consequences.** What would be removed can be reviewed before it is, and the
data card cannot drift from the corpus it describes — a hand-written card is
correct on the day it is written and wrong from the first change afterwards.

## Testing strategy

Five layers, each catching something the others cannot.

| Layer | Marker | For |
| --- | --- | --- |
| Unit | `unit` | Arithmetic and validation, in isolation |
| Integration | `integration` | Real files, the whole pipeline, the CLI **in-process** |
| Security | `security` | Adversarial input, and what must not appear in output |
| End-to-end | `e2e` | The CLI as a real subprocess, exit codes included |
| Meta | `meta` | Break one thing, assert the gate goes red |

The in-process CLI layer exists because **a subprocess is a different
interpreter** — invisible to coverage, with error paths nothing has ever
executed under assertion. Adding it here found a real bug in the first run:
`--records` and `--seed` were broken, because `Plan` is a slots dataclass with
no `__dict__` and the override used one.

The meta layer keeps the rest honest. It injects contamination at known rates
and asserts not only that the gate fires but that the rate it reports is an
estimate of the rate injected — the difference between a flag and a
measurement, and something only a test with a known answer can check.
